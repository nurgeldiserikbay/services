# ADR-0002: глобальный каталог с локальной выдачей по умолчанию
Статус: **accepted product decision; technical details proposed** · Дата: 2026-11-01

## Контекст
Services ориентирован на пользователей из разных стран и регионов. Люди должны быстро находить нужную услугу рядом с собой, но могут свободно искать в другом городе и стране. Для просмотра публичного каталога и контактов регистрация не нужна. Запуск предложения может начинаться в одном городе/нише, хотя архитектура глобальная.

## Решение
1. Международная структура справочников: country → administrative area → city, stable IDs, ISO-коды и локализованные алиасы; location, service area и delivery mode принадлежат предложениям, не только аккаунту.
2. Активный регион поиска определяется по приоритету: **ручной выбор на устройстве** → сохранённый выбор аккаунта при отсутствии нового локального выбора → добровольная точная геолокация по отдельному действию → осторожная приблизительная IP-подсказка → ненавязчивый ручной выбор.
3. Геолокация по GPS не запрашивается на первом открытии. Отказ не ограничивает использование сайта. Язык интерфейса не управляет регионом, смена IP/VPN не перезаписывает явный выбор.
4. Пользователь видит и может быстро изменить страну/область/город либо выбрать поиск по всей стране, по миру или среди онлайн-услуг.
5. В обычном режиме выдача сначала локальная, по фактической зоне обслуживания. Если подходящих предложений мало, UI **явно предлагает** расширить поиск. Далёкие результаты не маскируются под местные.
6. Поддерживаются разные способы услуги: в филиале, выездная в указанную зону, онлайн, гибридная. Цены, валюта и timezone конкретной услуги не выводятся из страны интерфейса.
7. Публичная страница специалиста, организации и предложения индексируется, если действительно опубликована и доступна. SEO canonical/hreflang, стабильные геоидентификаторы и noindex для пустых комбинаций фильтров.
8. Базовое присутствие специалистов и компаний в органическом каталоге бесплатно. Спонсируемые предложения отмечены рекламой и не покупают подлинную репутацию.
9. Регулируемые профессии, заключение договоров, трансграничная передача данных и платежи включаются **по стране** после отдельной правовой проверки. Глобальная навигация не обещает возможность оказания любой услуги в любом месте.

## Альтернативы
- Привязать каталог к Казахстану — отклонено из-за глобального продукта.
- Всегда показывать весь мир без локального контекста — отклонено из-за неудобной выдачи.
- Запрашивать GPS при запуске — отклонено по причинам приватности и конверсии.
- Автоматически переключать регион по новому IP — отклонено, поскольку ручной выбор приоритетнее.
- Тихо подмешивать соседние страны при нулевой выдаче — отклонено, интерфейс должен сообщать об изменении зоны.

## Архитектурные последствия
- Backend: GeoCatalog/LocationResolver/SearchScope, реальные ServiceArea/Offer delivery modes; публичные geo endpoints и ограниченный API предложения региона.
- Frontend: всегда видимый location switch, сохранение явного предпочтения, отдельный online filter, пустые состояния с expansion CTA.
- Admin: локализация географических алиасов, управление региональной доступностью категорий и запретами по юрисдикциям.
- Docs/OpenAPI: GEO-01..10, J-08..12, схематичные /geo endpoints и geography filters.
- Privacy: не хранить необязательные точные координаты, не использовать GPS в фоне, не делать местоположение публичной характеристикой человека.

## Приёмка
VPN сменил IP — ручной город сохранился; пользователь без входа переключил страну; отсутствие GPS не мешает поиску; выездная зона корректна; глобальный поиск не подменяет локальный без указания; одинаковые названия городов различаются; онлайн-услуги и валюты указаны явно.

## Открытые технические вопросы
Географический справочник/провайдер; точная стратегия TTL IP-предположения; языки вне kk/ru/en; кросс-валютное сравнение; правила SEO для больших стран; правовой запуск по каждой юрисдикции. Их решать до соответствующих production-функций.
