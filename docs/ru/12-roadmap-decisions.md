# 12. Roadmap, риски и открытые решения
> План v0.1 · Этапы зависят от проверки рынка

## Фазы
| Фаза | Результат / критерий выхода |
| --- | --- |
| 0. Discovery | 15–30 интервью с клиентами, мастерами, владельцами; подтверждены проблемы и привычные каналы |

| 6. Expansion | Новые профессии/категории, франшизы, масштабируемый поиск, интеграции |

## Ключевой сквозной сценарий
Компания создаёт филиал и offer «стрижка». Приглашает мастера, мастер подтверждает Affiliation и отдельный ServiceAssignment. Клиент находит мастера в команде, создаёт заявку, получает подтверждение, проходит визит и пишет два отзыва. Мастер завершает связь и добавляет новый салон. Клиент по подписке видит опубликованный переезд; отзыв о мастере остаётся с мастером, отзыв о старом салоне остаётся у салона.

## Основные риски и меры
- Холодный старт рынка → начальный сегмент и профили-линки, QR для привлечения собственной аудитории мастеров.
- Конфликт мастера и компании → независимые профили, явный продавец и роли, отсутствие передачи CRM.
- Поддельные отзывы → verified experience, жалобы, антифрод, ручная модерация на пилоте.
- Избыточный конструктор → готовые шаблоны, progressive disclosure, универсальные безопасные блоки.
- Юридический риск → классификация платформы, data mapping, отдельный review регулируемых категорий.
- Неуправляемая сложность → модульный монолит, горизонтальные рамки MVP, контрактное тестирование.

## Решения, требующие подтверждения
1. Финальный бренд, домен и товарный знак (пока рабочее имя Services).
2. Первый город и целевой сегмент.
3. Кто юридический продавец по каждому виду offer и сценарий возврата.
4. Метод подтверждения визита и политика споров по отзывам.
5. Период восстановления после удаления (предложение: 30 дней).
6. Точная политика доступности истории завершённых связей.
7. Инфраструктурный провайдер и регионы хранения.
8. Платёжный провайдер и экономика платных тарифов — после пилота.
9. Перечень регулируемых профессий, доступных к публикации и заказам.
10. Набор первых отраслевых шаблонов, которые реально нужны пилоту.

## Definition of Done для фичи
Доменное правило + UI state + API contract + ACL + аудирование + локализации kk/ru + миграции/тесты + accessibility + error/empty states + обновлённая документация. «На GitHub лежит код» не равно «работает на Android/iOS».
